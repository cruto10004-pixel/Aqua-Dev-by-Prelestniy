## 2. Что фактически сделано в round18

### Профиль и аватар

- Сохранены цвета, шрифты, нижняя навигация и общий язык Aqua. Новая композиция своей страницы профиля: компактный аватар/имя/честный локальный статус, три действия (фото, редактирование, настройки), данные, личный канал, музыка, избранное и ID.
- Кнопка фото читает локальный PNG/JPEG/WebP до 3 МБ, проверяет декодирование, уменьшает изображение до 960 px и сохраняет WebP в существующем хранилище профиля. Ошибка чтения/хранения показывает обратную связь. Никакой загрузки на сервер нет.
- Тап по круглому аватару раскрывает тот же элемент в квадрат. Повторный тап переносит **тот же DOM portrait**, а не новое изображение, в единственный viewer route. ResizeObserver сохраняет квадратную геометрию без растягивания по разным осям.
- Обратный переход возвращает portrait в исходную кнопку. Кнопка Back и история браузера восстанавливают раскрытое состояние. Прокрутка вниз более чем на 56 px от точки раскрытия сворачивает аватар. Автоматического повторного раскрытия при прокрутке вверх нет: раскрытие явным тапом. Отдельный pull-to-expand жест не добавлен.
- После редактирования аккаунта профиль показывает сохранённые изменения. Собственные имена/описания/подписи исключены из словарной замены текстов локализатором.

### Канал и музыка

- Канал — отдельная карточка с аватаром/fallback, названием, известным числом подписчиков, описанием и переходом в существующую страницу `peer`. Если число отсутствует, показано, что оно неизвестно; оно не выдумывается. Склонения подписчиков учитываются.
- При сохранении аккаунта `channelData` сохраняет снимок выбранного локального канала. После reload карточку можно открыть: снимок восстанавливается в локальный каталог с новым внутренним ключом. Публикации и сообщения этим не сохраняются.
- Музыка — обложка/fallback, название, исполнитель и кнопка. По умолчанию композиция отсутствует, кнопка отключена. Подготовлен необязательный объект `profile.music`; при наличии `src` кнопка действительно управляет HTMLAudioElement. Звук останавливается при навигации. UI прикрепления/удаления/каталог не сделаны.

### ID

- В `state.profile` отдельно предусмотрены `id: null` (будущий авторитетный серверный ID) и `localId`.
- `localId` создаётся при первом открытии профиля, имеет префикс `local:` и хранится в `aqua-preferences.profile`. Он не строится из телефона/юзернейма и не меняется при их редактировании.
- Информационное окно различает серверный и локальный ID; локальный ID можно копировать. Если предоставлен серверный `id`, предусмотрено отдельное действие копирования.
- Очистка браузерных данных меняет локальный ID. Он не гарантирует идентичность между устройствами и не является административным credential. Серверного генератора/проверки ID в проекте нет.

### Конфиденциальность

- Все 9 текущих параметров доступа (`phone`, `online`, `photo`, `forward`, `calls`, `voice`, `messages`, `birthday`, `gifts`) открывают единый собственный компонент Aqua вместо системного select.
- Используется уже существующий `#modal`: плавное открытие/закрытие, радиоиндикаторы, разделители, ограниченные размеры, две темы. Выбранный вариант получает фокус; стрелки перемещают фокус, Enter выбирает, Escape закрывает.
- Все/Мои контакты/Никто сохраняются локально; существующие исключения «разрешить» сохранены. При отказе localStorage выбор откатывается, окно остаётся доступным для повторного действия.
- Старые UI-actions `nav:privacy`, `nav:account`, `editprofile` направлены в существующие современные настройки, без второго навигационного стека. Другие select (например язык/автозагрузка) в этом этапе не заменялись.

### Фото и видео

- Используется тот же маршрут `viewer` в AquaPages. Ветка прежней статичной video-картинки удалена из `pages.js`, вместо неё вызывается AquaMedia.
- Фото показывается во встроенном экранном viewer. Для нескольких фото переписки работают предыдущая/следующая кнопки, клавиши влево/вправо, горизонтальный pointer-жест. Native HTML drag отключён, чтобы не мешать жесту. Ошибка загрузки фото отображается в viewer.
- Видео использует HTMLVideoElement **без native controls**, с `playsinline`; контролы рисует Aqua: воспроизведение/пауза, таймлайн, текущее время/длительность, громкость/mute, условный выбор качества, меню и fullscreen API.
- Контролы появляются/скрываются плавно, по тапу; при воспроизведении автоматически скрываются. Обновление времени не перезапускает таймер. Клавиатурный фокус не скрывается вместе с панелью.
- Выбор качества доступен только если сообщение содержит `qualities`. Источник меняется с восстановлением позиции. Дефолтных фиктивных 4K/1080p-опций нет.
- Ошибки загрузки/проигрывания дают понятное сообщение. Аудио/видео останавливаются при уходе/скрытии вкладки. Возврат сохраняет настоящий DOM и прокрутку предыдущего экрана.
- Viewer занимает весь viewport, в том числе landscape; фоновые rail/sidebar не занимают место поверх медиа.
- `assets/aqua-demo.webm` — созданный специально для прототипа синтетический 8-секундный ролик, 640×360, VP9/Opus, с тихим тоном. В UI он подписан как демо; в metadata указан CodeRabbit. Исходных реальных видео в архиве не было.
- `serve.py` добавлен из-за подтверждённой проблемы старого Python http.server с seek/quality. Он поддерживает обычный GET/HEAD и byte ranges через стандартную библиотеку Python. Для автономного HTML отдельный сервер не нужен.

## 5. Что осталось и что делать дальше

Проверить fullscreen/playsinline, звук/громкость (на iOS могут контролироваться системой), safe areas, клавиатуру, scroll/gesture interruption, фото и память на больших изображениях. Файлы: profile-media.*, gestures.js, pages.js. Не считать desktop touch-эмуляцию подтверждением работы физического iPhone.
2. **Музыка.** Нет разрешённого медиаисточника/каталога и интерфейса выбора композиции. Следующий шаг — согласовать источники и формат прикрепления; использовать уже предусмотренный profile.music, а не создавать второй проигрыватель.
3. **Backend ID, профиль, приватность.** Нет API/авторизации в этом standalone. При интеграции назначать profile.id только из доверенного ответа сервера; localId не отправлять как доказательство личности. Сохранить различие username/id. Реальные исключения должны ссылаться на серверные user IDs.
4. **Каналы.** Снимок channelData сохраняет сведения, но не сообщения/публикации. Дальше — серверный channelId и загрузка по нему вместо текущей legacy-связи по имени. Не выдавать новый локальный ключ после reload за прежний серверный ID.
5. **Галерея/видео.** Pinch zoom и панорамирование фото не добавлялись. Потоковый HLS/DASH, транскодирование/генерация качества и серверная выдача медиа отсутствуют. Сначала получить источники и необходимость этих возможностей, не добавлять тяжёлый плеер заранее.
6. **Широкая регрессия.** Старые сценарии чатов/дока/регистрации полностью не повторялись. Нужны отдельные device-проверки при следующей итерации. Текущие переходы профиля/media/настроек и затронутые возвраты проверены.
7. **Storage.** localStorage ограничен квотой, зависит от origin и режима браузера. Ошибки отображаются; очистка удаляет локальный ID/фото. Для больших медиаданных в будущем нужен отдельный согласованный слой хранения/API, а не увеличение data URL без ограничений.

## 6. Технические решения для продолжения

- Проект — обычные scripts, без сборщика/framework/package manager. Порядок в index.html важен: settings → pages → profile-media → app, затем locale/gestures/dock. Модули используют общие state/messages/chats, `$`, icon, avatar, esc.
- Существующий `AquaPages` хранит frames с реальными DOM nodes, model, focus, scroll и state.page/chat/mobile; History API обеспечивает Back. Нельзя создавать параллельный стек для медиа или аккаунта.
- `AquaMedia.render(model)` обслуживает тот же viewer route. `capture` вызывает suspend, `place` вызывает mount/restored. При уходе portrait возвращается в origin до восстановления frame. Не заменять его тремя независимыми изображениями.
- Motion: существующая Anime.js **4.5.0** (локальный vendor) управляет часами AquaMotion/WAAPI. Новые переходы используют AquaMotion, учитывающий prefers-reduced-motion и power saving. CSS transition применяется только к состояниям видимости media controls. Новых JS-зависимостей нет.
- Приватность использует `#modal` и существующие modal/closeModal; не добавлять второй dialog manager. В `settings.js`: `accessControl`, `accessOptions`; ключи `access-{key}`, `exception-{key}-{localChatId}`.
- Настройки и профиль: JSON `aqua-preferences`; `state.settings.profile` и `state.profile` должны обновляться только после успешного persist. `draft` формы живёт в AquaSettings. Фото сохраняется здесь же. Серверные данные не загружаются.
- Контракт music: необязательный `{ title, artist, cover?, src? }`. Пустой блок не содержит выдуманной песни. UI управления прикреплением — будущая работа.
- Контракт media: `message.photo` + `photoSrc?`; `message.video` + `videoSrc?`, `poster?`, `qualities?: [{label, src}]`. Старые demo messages без src используют локальные fixtures. Имеющаяся модель сообщений остаётся совместимой.
- `serve.py` нужен именно для медиапроверок по HTTP. Python stdlib, диапазоны bytes, suffix/open-ended, HEAD и 416. FFmpeg использовался только для создания приложенного fixture, пользователю для запуска не нужен.
- `build-standalone.py` встраивает подключённые CSS/JS и assets как data URL. После каждого изменения пересобирать; standalone не первоисточник кода.
